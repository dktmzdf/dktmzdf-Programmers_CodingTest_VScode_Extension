# 코딩테스트 에이전트

프로그래머스 스쿨 문제를 VS Code 안에서 불러오고, 로컬에서 테스트하고, 제출하고,
막히면 클로드에게 힌트를 받는 확장.

풀이 과정은 전부 `problems/` 아래에 파일로 남는다.

## 쓰는 법

| 하는 일 | 방법 |
| --- | --- |
| 패널 열기·닫기 | `Ctrl+Alt+P` 또는 액티비티 바의 `</>` 아이콘 |
| 문제 불러오기 | 패널 위쪽에 문제 URL(또는 문제 번호)을 붙여넣고 **불러오기** |
| 로컬 테스트 | **▶ 로컬 테스트** 또는 `Ctrl+Alt+T` |
| 테스트 케이스 추가 | 테스트 케이스 옆 **+ 추가** |
| 제출 | **☁ 제출 후 채점** (로그인 쿠키 필요) |
| 해설 | **💡 힌트 / 🗺️ 접근법 / 📖 전체 해설 / 🔍 코드 진단** |

문제 번호만 넣어도 된다. `181950` 과
`https://school.programmers.co.kr/learn/courses/30/lessons/181950?language=python3` 는 같다.

## 프로그래머스 로그인 (제출할 때만 필요)

문제를 읽고 로컬 테스트를 돌리는 데는 로그인이 **필요 없다.** 제출할 때만 필요하다.

### 로그인 순서

1. VS Code 패널의 **브라우저에서 로그인**을 누른다
2. 확장이 연 전용 Chrome 또는 Edge 창에서 프로그래머스에 로그인한다
3. 로그인이 확인되면 브라우저 창이 자동으로 닫힌다

이미 전용 프로필에서 로그인한 적이 있으면 다음에는 로그인 상태를 바로 확인한다. 일반 로그인,
소셜 로그인, 2단계 인증은 모두 브라우저 안에서 직접 처리하며 확장은 아이디나 비밀번호를 읽지 않는다.

### 안전

- 제출에 쓰는 세션은 VS Code **SecretStorage(암호화)** 에 저장된다
- 자동 로그인용 전용 브라우저 프로필은 VS Code 확장 저장소에만 둔다
- 확장은 `programmers.co.kr` 쿠키만 수집하며 쿠키 값을 로그나 파일에 출력하지 않는다
- `코딩테스트: 프로그래머스 로그아웃`은 세션과 전용 프로필을 함께 삭제한다

### 잘 안 될 때

| 증상 | 해결 |
| --- | --- |
| Chrome 또는 Edge를 찾지 못함 | `codingTest.browserPath`에 브라우저 실행 파일 경로를 지정한다 |
| 로그인 창이 바로 닫힘 | Chrome/Edge를 업데이트하고 다시 시도한다 |
| 5분 안에 확인하지 못함 | 로그인 완료 후 프로그래머스 문제 페이지가 열리는지 확인한다 |
| 세션이 만료됨 | **브라우저에서 로그인**을 다시 실행한다 |

## 남는 파일

```
problems/181950-문자열-반복해서-출력하기/
├─ problem.md         문제 전문
├─ solution.py        내 코드          ← 다시 불러와도 덮어쓰지 않는다
├─ testcases.json     공식 예제 + 내가 추가한 케이스
├─ result.md          채점 결과 이력
└─ explanation.md     받은 힌트·해설 이력
```

## 설정

| 설정 | 기본값 | 설명 |
| --- | --- | --- |
| `codingTest.problemsRoot` | (비움) | 문제 폴더 위치. 비우면 워크스페이스의 `problems/` |
| `codingTest.pythonPath` | (비움) | 비우면 Python 확장이 고른 인터프리터 → `python` |
| `codingTest.browserPath` | (비움) | 자동 로그인 브라우저. 비우면 Chrome → Edge 순으로 탐색 |
| `codingTest.timeoutMs` | `5000` | 테스트 케이스 하나당 제한 시간 |
| `codingTest.claudePath` | (비움) | 비우면 `PATH` 의 `claude` |
| `codingTest.claudeModel` | `sonnet` | 해설 생성 모델 |

해설은 Claude Code CLI(`claude`)를 헤드리스로 부른다. 이미 로그인돼 있으면
API 키를 따로 발급할 필요가 없다.

## 지원 범위

프로그래머스의 두 문제 형식을 모두 지원한다. 형식은 페이지가 알려 주므로 자동으로 가른다.

| 형식 | 생김새 | 로컬 테스트 |
| --- | --- | --- |
| **표준입출력형** | `input()` 으로 읽고 `print` 로 출력 | 표준입력을 넣고 표준출력을 비교 |
| **함수형** | `def solution(a, b):` 가 값을 return | `solution(a, b)` 를 부르고 반환값을 비교 |

언어는 파이썬만.

### 함수형에서 알아둘 것

- `solution.py` 에는 **아무것도 심지 않는다.** 제출하는 파일과 글자 하나 다르지 않다.
  실행은 확장이 별도 파이썬 실행기를 통해 함수만 부르는 방식이다
- 그래서 `solution.py` 를 VS Code의 ▷ 버튼으로 직접 실행해도 아무 일도 일어나지 않는다.
  **패널의 ▶ 로컬 테스트** 를 쓴다
- 코드 안에서 `print()` 를 찍으면 반환값과 **따로** 표시된다. 디버깅에 그대로 쓰면 된다
- 케이스를 직접 추가할 때 값은 **파이썬 리터럴**로 쓴다
  — 문자열은 `"따옴표"`, 배열은 `[1, 2, 3]`, 참/거짓은 `True` / `False`
  (사이트가 표에 적어 둔 `true` / `false` 도 그대로 읽는다)

## 설치·개발

Node.js도 빌드도 필요 없다. 소스가 그대로 확장이다.

```powershell
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.vscode\extensions\coding-test-agent" `
  -Target "C:\Work\PythonProject\CodingTestAgent\extension"
```

그 다음 `Ctrl+Shift+P` → `Developer: Reload Window`.
소스를 고치면 창만 새로고침하면 바로 반영된다.

## 테스트

```powershell
.\test\run.ps1
```

Node를 설치하지 않아도 된다 — VS Code에 딸려 오는 Node를 빌려 쓴다.
파이썬이 있으면 로컬 실행기까지 실제로 돌리고, 없으면 그 부분만 건너뛴다.

| 무엇을 | 어떻게 |
| --- | --- |
| 구문·제어문자 | 확장의 모든 `.js`/`.json` 을 파싱 (빌드 단계가 없어 문법 오류가 런타임까지 숨는다) |
| HTML → Markdown | 코드 블록 보존, 표 변환, 중첩 `div` 균형 |
| 웹뷰 렌더러 | 코드 펜스·목록, **HTML 주입 차단** |
| 파서 | 픽스처 9개로 `type`·시그니처·케이스·채점 id |
| 로컬 실행기 | 정답·오답·예외·타임아웃·`print` 캡처, `__pycache__` 미생성 |

**이 확장은 프로그래머스 페이지 구조에 의존한다.** 사이트가 개편되면 조용히 깨지는데,
이 테스트가 어디가 깨졌는지 알려 주는 유일한 안전망이다. 뭔가 이상하면 먼저 돌려 본다.

픽스처(문제 페이지 스냅샷)를 다시 받으려면 `test\fixtures\refresh.ps1`.
자세한 내용은 [test/fixtures/README.md](test/fixtures/README.md).

## 주의

프로그래머스는 공개 API가 없어서 브라우저가 쓰는 것과 같은 요청을 흉내낸다.
본인 계정으로 본인 코드를 제출하는 용도로만 쓰고, 사용자가 버튼을 누를 때만 요청한다.
사이트가 개편되면 깨질 수 있으며, 그때는 저장소의 `docs/programmers-api.md` 를 보고 고치면 된다.
